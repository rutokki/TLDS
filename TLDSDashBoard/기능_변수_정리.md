# 기능 · 동작 방식 정리 (cs 파일별)

`TLDSDashBoard` WPF 프로젝트의 **.cs 파일마다 무엇을 하고 어떻게 동작하는지**, 그리고 값을 바꿀 때 찾아가야 할
상수·메서드를 정리한 레퍼런스입니다. 실행·배포 절차는 `../README.md`를 참고하세요.

> 기준: 2026-10-07 커밋 `d2251a7` 이후 코드 (실데이터 전용 · system.xml 기반 역/궤도 · 6채널 구조)

---

## 1. 전체 구조 한눈에 보기

### 1-1. 데이터 파일 → 코드

TLDSDashBoard.exe는 **TLDS 설치 폴더(TLDS.exe 옆)** 에 두고 실행하며, exe 옆의 `_file_*` 폴더를 읽기 전용으로 엽니다.
샘플/가짜 데이터는 없습니다 — 파일에 없으면 화면은 비어 있고 사유를 표시합니다.

| 파일 | 내용 | 읽는 코드 |
|---|---|---|
| `_file_system/system.xml` | 이 설치가 담당하는 역(`<station_no><match number name/>`) | `StationConfigLoader` |
| `_file_system/index_{역}.xml` | 궤도회로 목록(`<track><contents index name type level_type/>`), LEU 입력카드 | `StationConfigLoader` |
| `_file_system/rack_{역}.xml` | 궤도별 임펄스 랙/슬롯 배선 | `StationConfigLoader` |
| `_file_log/{yyyy}/{MM}/{yyyy-MM-dd-HH}.db` | 1시간 1파일, 측정값 테이블 `Level12`(구버전 `Level01`): `Time, Idx, Type, Value0..11` | `RealTelemetryRepository` |
| `_file_db/SetValue.db` | 장치별 기준값 `Level01`: `Base_N / Caution_N / Warning_N` | `ThresholdRepository` |
| `_file_db/Event-{yyyy-MM-dd}.db` | 1일 1파일, `Event`(이벤트), `Alarm`(알람) 테이블 — 문자열은 CP949 | `EventLogRepository` |

- 장치 번호: `index_{역}.xml`의 `index` = 로그의 `Idx` = SetValue의 `ObjectIndex` (`TrackCircuit.Idx`)
- 채널: 로그 `Value0..5` = 기준값 `_0.._5` = `ChannelCatalog` 순서 (궤도/차상/지상 주파수, 송신/수신A/수신B 전압). `Value6..11`은 읽지만 사용하지 않음.

### 1-2. 시작 흐름

```
App.OnStartup
 ├─ TldsDataPaths.SetRoot(--data-root 인자 / TLDS_DATA_ROOT 환경변수)   ← 없으면 exe 폴더
 ├─ ReferenceData.Current  → StationConfigLoader.Load()                 ← 실패 시 오류창 후 종료
 └─ new MainWindow()  → DataContext = new MainViewModel()
        ├─ 하위 페이지 VM 5개 생성 (그래프 상세검색/열차점유/궤도장애/레벨기록/시간별상태)
        ├─ LoadChannelData()   : 선택 장치의 [지금-10분, 지금] 로그 조회
        ├─ BuildStaticData()   : 주파수/전압 레인 차트 구성
        ├─ BuildAlarmData()    : 최근 10분 알람
        └─ 타이머: 1초(시계), 60초(위 3개 재실행)
```

## 2. 루트

### `App.xaml.cs`
- **역할**: 프로그램 진입점. `App.xaml`에 `StartupUri`가 없고, 여기서 직접 창을 만듭니다.
- **동작**
  1. 생성자: `CodePagesEncodingProvider` 등록 — CP949(한글 ANSI) 디코딩용(Event DB, 설정 XML).
  2. `OnStartup`: 데이터 루트 결정 → `TLDS_DATA_ROOT` 환경변수, 그 다음 `--data-root <경로>` 인자가 우선.
  3. `ReferenceData.Current`로 역/궤도 설정을 미리 로드. 실패하면 무엇이 없는지 MessageBox로 알리고 `Shutdown(1)`.
  4. 성공 시 `MainWindow` 생성·표시.
- **고칠 때**: 시작 시 검사 항목 추가는 `OnStartup`의 try 블록.

### `MainWindow.xaml.cs`
- `DataContext = new MainViewModel()` 한 줄. 화면 조립은 `MainWindow.xaml`(사이드바 + 상단바 + 페이지 5개를 겹쳐 두고 `Is…Active`로 하나만 표시 + 모달/토스트 오버레이).

## 3. Models — 데이터 구조 (로직 없음)

| 파일 | 내용 |
|---|---|
| `ChannelDataSet.cs` | 한 장치·한 구간의 시계열. `Timestamps`(DateTime[]) + 채널 6개 `double[]`(`TRK_FREQ, CAB_FREQ, CODE_FREQ, TX_VOLTAGE, RX_A_VOLTAGE, RX_B_VOLTAGE`). `Get(id)`로 채널 id 문자열로 배열을 꺼냄(카탈로그 루프용). |
| `ChannelMeasurement.cs` | 표준/측정/점검/최소 4값 묶음. `Measured`는 `double?` — 실측값이 없으면 null(표에서 빈칸, 추정값 넣지 않음). |
| `TrackFaultRecord.cs` | 궤도 장애·경보 한 행: 궤도명/일자/발생·복구시각/장애종류/IMP/AF/궤도타입 + 채널 6개 `ChannelMeasurement`. |
| `LevelRecord.cs` | 레벨 기록 한 행(1초 = 1행): 역/궤도/기록일자/시간대/시각 + 채널 6개 `ChannelMeasurement`. |
| `MetricDef.cs` | OverView 차트용 채널 정의(Id/Name/Unit/Color/Data). `Decimals`: 단위가 Hz면 소수 2자리, 그 외 1자리. |
| `AlarmEventModel.cs` | OverView "최근 10분 알람" 한 행(시각/장치명/내용/심각도). `AlarmSeverity`: Info/Warning/Critical. |
| `Station.cs` | 역(`Id`=system.xml의 number, `Name`). |
| `TrackCircuit.cs` | 궤도회로. `Idx`(DB 장치번호), `LevelType`(IMP_I/AF_BS), `TrackType`(NT/PT/BT), 랙 정보(`RackName/RackNo/RackSlot`), 표시용 `RackLabel`("임펄스랙1번 · 슬롯 3 · IMP_I"). `Id`는 "역번호:이름"으로 역 간 이름 중복에도 유일. |
| `TrainOccupancyRecord.cs` | 열차점유 한 행(진입/통과/점유시간). 현재 채워지는 곳 없음. |
| `HourlyStatusEventRecord.cs` | 시간별 상태 출력 한 행 + 7개 카테고리 enum(`HourlyStatusCategory`). |

## 4. Services — 데이터 읽기 · 계산

### `TldsDataPaths.cs`
- **역할**: 모든 데이터 파일 경로의 단일 출처.
- **동작**: `Root` = `SetRoot()`로 지정한 경로, 없으면 `AppContext.BaseDirectory`(exe 폴더).
  - `FileLogRoot`, `FileDbRoot`, `FileSystemRoot`
  - `HourLogFile(시각)` → `_file_log\yyyy\MM\yyyy-MM-dd-HH.db`
  - `EventDbFile(날짜)` → `_file_db\Event-yyyy-MM-dd.db`, `SetValueDbFile`
- **고칠 때**: 파일 이름 규칙이 바뀌면 여기만 수정.

### `StationConfigLoader.cs`
- **역할**: `_file_system`의 XML을 읽어 역/궤도/LEU/랙 정보를 만듭니다 (TLDS.exe와 같은 규칙).
- **동작**
  1. `system.xml`의 `<station_no><match number name/>`에서 역 목록. 없으면 `<menu><section name>` 사용.
  2. 역마다 `index_{역이름}.xml`의 `<track><contents>` → `TrackCircuit` (index→`Idx`, name, type, level_type). `<input>`의 `DICARD` → LEU 목록.
  3. `rack_{역이름}.xml`의 `<sub type="impulse">` → `<card slot>` → `<track name>`으로 궤도별 랙/슬롯 매핑. 파일이 없으면 랙 정보만 비움.
  4. 결과: `StationConfig(Stations, Tracks, LeuDevices, Warnings)`. 경고 예: `rack_xx.xml 없음`, `rack에만 있는 궤도(무시됨): 27T`.
- **특이사항**
  - XML은 인코딩 선언 없는 **CP949** → 바이트로 읽어 BOM/UTF-8 검사 후 CP949로 디코딩.
  - 현장 파일에 규격 위반 주석(`<!-- ... "---" ... -->`)이 있어 **파싱 전 모든 주석을 제거**.
  - `system.xml`이 지정하지 않은 `index_*.xml`은 폴더에 있어도 무시.
- **예외**: system.xml 없음 / 역 정보 없음 / 궤도 0개 → 예외(→ App이 오류창 표시).

### `ReferenceData.cs`
- **역할**: 각 페이지 콤보박스가 쓰는 역/궤도 목록. `Lazy<StationConfig>`로 **최초 접근 시 1회** `StationConfigLoader.Load()`.
- 제공: `Stations`, `Tracks`, `LeuDevices`(미사용), `TracksForStation(역Id)`, `Current`(전체 결과).

### `ChannelCatalog.cs`
- **역할**: 채널 6개의 id/이름/단위/색상/그룹의 **단일 출처**. 배열 순서 = 로그 `Value0..5` = 기준값 인덱스.

  | Id | 이름 | 단위 | 그룹 |
  |---|---|---|---|
  | `TRK_FREQ` | 궤도 주파수 | Hz | 주파수 |
  | `CAB_FREQ` | 차상 주파수 | Hz | 주파수 |
  | `CODE_FREQ` | 지상 주파수 | Hz | 주파수 |
  | `TX_VOLTAGE` | 송신 전압 | V | 전압 |
  | `RX_A_VOLTAGE` | 수신 A 전압 | V | 전압 |
  | `RX_B_VOLTAGE` | 수신 B 전압 | V | 전압 |

- 메서드: `ChannelIds`, `ChannelCount`, `ChannelName/Unit/Color/Group(id)`, `IndexOf(id)`.
- **채널을 추가/변경할 때 함께 고칠 곳**: 이 파일 + `ChannelDataSet`(프로퍼티·`Get`) + `RealTelemetryRepository`(Value 매핑) + `TrackFaultRecord`/`LevelRecord`(프로퍼티) + 두 VM의 행 생성·CSV + 두 표 XAML의 헤더/컬럼.

### `IChannelDataRepository.cs` / `RealTelemetryRepository.cs`
- **역할**: 측정 로그 조회. 인터페이스는 `LoadRange(장치Idx, 시작, 끝)` 하나.
- **동작**
  1. 시작 시각의 정시부터 끝까지 **1시간씩** `HourLogFile`을 확인, 있는 파일만 읽기 전용으로 엶(TLDS.exe가 쓰는 중이어도 가능).
  2. 파일마다 `sqlite_master`에서 테이블명 확인 → `Level12` 우선, 없으면 `Level01`.
  3. `WHERE Idx=@장치 AND Type=0 AND Time BETWEEN @시작 AND @끝 ORDER BY Time` (`Time`=유닉스초 → 로컬 시각 변환, `Type=0`=측정값, `1`=상태 플래그는 미사용).
  4. `Value0..5`를 채널 6개 배열로 묶어 `ChannelDataSet` 반환.
  5. **한 건도 없으면 `InvalidOperationException`** — 호출하는 쪽이 "데이터 없음"으로 처리.

### `ThresholdRepository.cs`
- **역할**: `SetValue.db`의 장치별 기준값.
- **동작**: `SELECT * FROM Level01 WHERE ObjectIndex=@idx ORDER BY Time DESC LIMIT 1` → 채널 수(`ChannelCount`)만큼 `Base_i/Caution_i/Warning_i`를 `ChannelThreshold(Base, Caution, Warning)`로. 파일/행이 없으면 null.
- `ToMeasurement(기준, 측정값?)`: 표준=Base, 점검=Caution, 최소=Warning, 측정=전달값.
- **주의**: 현재 SetValue 값은 예전 채널 기준(예: 226/158/113)이라 새 6채널 값(1700Hz 등)과 단위가 맞지 않을 수 있음.

### `EventLogRepository.cs`
- **역할**: `Event-{날짜}.db` 읽기. 파일이 없으면 빈 목록(예외 아님).
  - `LoadEvents(날짜)` → `EventLogRow(시각, DEVICE_TYPE, 장치명, 내용)`
  - `LoadAlarms(날짜)` → `AlarmLogRow(발생시각, 복구시각?, 장치명, 내용, MAJOR, MINOR)` (`RESTORE_TIME`이 0이면 미복구)
- **특이사항**: `DEVICE_NAME/CONTENTS`는 CP949 바이트라 `CAST(... AS BLOB)`으로 읽어 직접 디코딩, NUL 이후 잘라냄.

### `PathBuilder.cs`
- **역할**: 숫자 배열 → WPF `Path` 문자열("M x,y L x,y …"). 차트는 전부 이 문자열을 `Viewbox Stretch=Fill` 위 고정 캔버스에 그림.
- 메서드
  - `PathFromArray(arr, min, max, w, h, padTop, padBottom)`: 지정한 축 범위로 좌표 계산.
  - `HorizontalLinePath(값, …)`: 점검/최소 기준선(같은 축 스케일).
  - `ComputeReferenceLines(window, 점검, 최소)`: 실제 기준값과 데이터 범위를 모두 포함하도록 축(min/max) 확장.
  - `ComputeReferenceLines(window)`: 기준값이 없을 때 데이터 폭 ±15%로 임시 기준선 계산.
  - `Downsample(arr, maxPoints)`: 구간별 min/max를 남기는 축약(스파이크 보존) — 그래프 상세검색의 줌/팬 성능용.
  - `PathFromArrayAutoRange`: 배열 자체 min/max 사용(현재 미사용).

### `ChartMetrics.cs`
- 차트 가상 캔버스 크기 상수. **XAML의 `Canvas Width/Height`와 반드시 같아야 함.**
  - `LaneChartW/H/Pad` = 900/90/10 (OverView·그래프 상세검색 레인)
  - `DrillChartW/H/Pad` = 900/240/16 (채널 확대 모달)
  - `OverlayChartW/H/Pad` = 1400/460/16 (현재 미사용, 예전 오버레이 차트 잔재)

### `CsvExporter.cs`
- **역할**: 모든 "CSV 저장" 버튼 공통. 저장 대화상자 → **UTF-8 BOM**(엑셀 한글 깨짐 방지) → 쉼표/따옴표/줄바꿈 이스케이프.
- 파일이 열려 있거나 권한이 없으면 예외 대신 MessageBox 후 null 반환.
- `FlattenChannel(ChannelMeasurement)` → "표준,측정,점검,최소" 4칸(F2), `MeasurementSuffixes` = 헤더 접미사.

## 5. ViewModels — 화면 상태와 동작

### `ViewModelBase.cs` / `RelayCommand.cs`
- `ViewModelBase`: `INotifyPropertyChanged` + `SetProperty(ref 필드, 값)` (값이 바뀔 때만 알림).
- `RelayCommand`: 버튼 `Command` 바인딩용 `ICommand` (파라미터 없는/있는 생성자 2종).

### `DateRangeFilter.cs`
- 기간 필터(시작일·시·분 ~ 종료일·시·분). 기본값 오늘 00:00 ~ 23:59. `Start`, `End`(끝은 59초 포함) 계산 프로퍼티.
- 열차점유/궤도장애/레벨기록/시간별상태/그래프 상세검색이 공용으로 사용 (`DateRangeFilterView`가 바인딩).

### `MainViewModel.cs` — 앱 전체 + OverView
- **역할**: 사이드바 내비게이션, 상단바(시계·데이터소스 배지), OverView 페이지 전체, 채널 확대 모달, 토스트.
- **상태 / 바인딩 속성**
  - 내비게이션: `NavItems`, `ActivePageTitle`, `IsGraphActive` 등 페이지별 표시 플래그. `NavClickCommand("hourlystatus")`는 페이지 전환 대신 모달(`HourlyStatus.Open()`).
  - 장치: `AvailableTracks`, `SelectedTrack` — **바꾸는 즉시** `GraphSearch()` → 다시 로드·그리기.
  - 차트: `FrequencyChart`, `VoltageChart` (`CombinedChartVM`, 데이터 없으면 null).
  - 상태: `IsRealData`, `DataSourceLabel`(배지 문구), `DataSourceDetail`(툴팁: 건수·마지막 수신·경로), `ChannelDataEmptyMessage`(빈 화면 사유), `RecentAlarms`, `AlarmEmptyMessage`, `ClockLabel`.
- **동작 순서**
  1. `LoadChannelData()`: `LoadRange(SelectedTrack.Idx, 지금-10분, 지금)`. 실패 시 `_channelData=null` + 사유 메시지(현재 시간대 로그 파일이 없으면 "TLDS 프로그램 실행 확인" 안내와 파일 경로).
  2. `BuildStaticData()`: `ChannelCatalog` 순서로 `MetricDef` 6개 생성 → `SetValue` 기준값 로드(`_thresholds`에 캐시) → 그룹(주파수/전압)별로 `BuildChart` → 레인마다 축 범위·경로·기준선·최신값 계산.
  3. `BuildAlarmData()`: 지금-10분 ~ 지금 사이의 `Alarm` 행(자정을 넘으면 이틀치). 미복구=Critical, 복구=Info(+"복구 HH:mm:ss"). 최신순.
  4. 타이머: `_clockTimer` 1초(시계), `_refreshTimer` 60초(1~3 + 열려 있는 확대 모달 갱신). **장치 변경은 알람을 다시 읽지 않음**(알람은 전체 장치 대상).
- **채널 확대 모달 (드릴)**
  - `OpenDrill(id)` → `RecomputeDrill()`: 그 채널의 표시 구간으로 큰 차트·최소/최대/평균·기준선(레인과 같은 SetValue 값).
  - `ZoomDrill(배율, 커서위치)`: 커서 아래 지점을 고정한 채 표시 샘플 수 조절(최소 10개). `PanDrill(이동비율)`, `ResetDrillZoom()`, `UpdateDrillHover/ClearDrillHover`.
- **내보내기**: `ExportCsvCommand` — 모달이 열려 있으면 그 채널 전체, 아니면 10분 구간 6채널. `ExportPngCommand`는 토스트만 띄우는 **미구현** 상태.

### `GraphDetailSearchViewModel.cs` — 그래프 상세검색
- **역할**: 지정 기간(기본 최근 1시간)·장치의 6채널을 레인으로 쌓아 표시. 줌/팬/호버가 모든 레인에 동시에 적용.
- **동작**
  1. `Search()`(조회 버튼): `LoadRange` → 채널별 배열 저장, 기준값 로드, `Series`에 레인 6개 생성. **대체 데이터 없음** — 없으면 레인을 비우고 `StatusMessage`에 사유.
  2. `Recompute()`: 현재 창(`_windowStart`, `_windowLength`)만큼 잘라 `Downsample`(최대 400점) 후 경로·축·기준선 갱신. 레인 객체는 재사용(in-place 갱신)해서 줌/팬이 끊기지 않음.
  3. `Zoom(배율, 커서비율)`, `Pan(이동비율)`, `ResetZoom()`, `UpdateHover(비율)`/`ClearHover()`.
- **세로 크기**: `SetBaseLaneHeight`(뷰가 화면 높이 ÷ 채널 수로 전달), `AdjustLaneZoom`(1~6배), `ResetLaneZoom`, `HasVerticalOverflow`(확대됐을 때만 세로 스크롤바), `IsVerticalZoomMode`(휠을 세로 확대로 사용).
- **표시 토글**: `ShowMeasuredLine`(측정선), `ShowReferenceLines`(점검/최소선).
- **상수**: `MaxRenderPoints = 400`.

### `TrackFaultListViewModel.cs` — 궤도 장애/경보
- **필터**: 기간, 역, 궤도(“전체 궤도” 포함), 상태(전체상태/발생중/복구됨).
- **동작** `Search()`
  1. 기간의 날짜마다 `LoadAlarms(날짜)` → 기간 안 + **장치명이 선택 궤도 이름과 일치**하는 알람만.
  2. 궤도별 `SetValue` 기준값이 없으면 그 알람은 제외.
  3. 측정값: 알람 발생 시각부터 60초 안의 첫 로그 샘플. 없으면 빈칸(null).
  4. 상태 필터(발생중=복구시각 없음, 복구됨=있음) 적용 → 결과/건수 표시. 없으면 "기록이 없습니다".
- IMP/AF 칸은 Alarm 테이블에 해당 정보가 없어 빈칸. `PrintCommand`는 **미구현**(문구만 표시).

### `LevelRecordListViewModel.cs` — 레벨 기록 리스트
- **필터**: 역, 궤도(기본: 첫 궤도), 기간.
- **동작** `Search()`
  1. 기간이 `MaxSpan`(2시간)을 넘으면 **기간 안에서 로그 파일이 있는 첫 시간부터 2시간**만 조회(하루 전체를 골라도 데이터가 있는 구간이 나오도록).
  2. 궤도마다 기준값 + `LoadRange` → **1초 = 1행** `LevelRecord`(표준/점검/최소는 기준값, 측정은 그 초의 실측값).
  3. 결과는 `Results`를 통째로 교체(행 수만~수만 개를 하나씩 Add하면 UI가 멈추기 때문).
- 상태 메시지에 2시간 제한으로 잘린 실제 구간을 표시. 전체 궤도 1시간 ≈ 3~4만 행(약 2초).

### `TrainOccupancyViewModel.cs` — 열차점유리스트
- 필터(기간·역·궤도)와 CSV는 있으나 **실데이터 소스가 확인되지 않아 조회 결과는 항상 비어 있음**.
  (`_file_log`의 `OutValue01/12(Time, Len, Status BLOB)`가 후보이나 형식 미확인.)

### `HourlyStatusViewModel.cs` — 시간별 상태 출력(모달)
- **동작**
  1. `Open()`: 모달 열기 + 즉시 `Search()`.
  2. `Search()`: 기간의 날짜마다 `LoadEvents` → 장치명 키워드로 7개 카테고리 분류(`CategorizeByDeviceName`: LEU/전환기/신호기/폐색/궤도/임펄스랙·연동장치·TLDS=시스템/그 외=신호설비) → "다음 시간대 제외"(기본 0~4시) 적용.
  3. 왼쪽 카테고리 선택(`SelectedGroup`)은 표시만 바꿈(재조회 없음). CSV는 현재 카테고리만 저장.
- **미구현/임시**: 조건 체크박스(`ConditionOptions`, 카테고리마다 같은 5개)는 표시만 되고 필터링에 쓰이지 않음. DEVICE_TYPE 코드표가 없어 이름 키워드로 분류. `PrintCommand` 미구현.

## 9. 미구현 · 확인 필요 목록

- 열차점유리스트: 실데이터 소스 미확인 → 항상 빈 결과.

- 미사용 코드: `MetricCardVM`, `BoldWhenTrueConverter`, `ChartMetrics.OverlayChart*`, `PathBuilder.PathFromArrayAutoRange`, `ReferenceData.LeuDevices`.
